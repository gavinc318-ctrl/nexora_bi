# 假 ICP 接口服务

开发期测试工具，**不交付**（AS-32）。开发机连不上真实的 ICP，接入程序在开发期调用它。

## 原则

- **照接口文档实现**与真实接口相同的请求与响应：鉴权、`cmsgateway-token`、窗口上下限
  （≤24 小时、≥5 秒）、不支持并发、CSV 附件、`result` 响应头。
- **接入程序里不得有「合成模式」分支**。调用假接口与调用真实接口的唯一差别，是部署时注入的
  地址与账号。否则鉴权、窗口与并发这些代码路径在开发期一次都没被执行过。
- 文档没写清、只能猜的行为，在代码里标为「猜 N」，编号对应 NOTES.md「假设登记草稿」第三节。
  **每一条都是联调核实项**：联调时必须逐条主动核实，不能以「跑通了」为准。
- 合成数据的比例是编的，**不得用于性能结论或指标口径结论**，只用于验证代码路径。

## 启动

```bash
python3 test/fake_icp/server.py --port 18080 --seed 1 --account <工号>:<口令>
```

账号必须显式给出，仓库里不留任何口令，哪怕是假接口的。只监听 127.0.0.1。

| 参数 | 含义 |
| --- | --- |
| `--seed` | 合成数据的种子。同一种子、同一窗口、同一「此刻」，返回内容完全相同 |
| `--token-ttl` | token 有效期（秒），默认 600。开发期设短，让鉴权重取的路径常被走到 |
| `--emit-mode` | `on_leave`（默认）：腿离开设备时才出现；`on_enter`：一进入设备就出现，字段随时间补齐，整通结束时末腿由正序号改为 -1（猜 15） |

## 测试用的控制端点（真实接口没有，接入程序永远不调）

```bash
# 把「此刻」固定在某个时间（不传则用真实 UTC 时间）
curl -s -X POST localhost:18080/_fake/control -d '{"now": "2026-10-14 12:00:00"}'

# 下一次下载混入边界数据（用一次即清）
curl -s -X POST localhost:18080/_fake/control \
  -d '{"inject": ["inversion", "null_waitbegin", "unknown_calltype", "dup_callidnum", "comma_in_callerno"]}'

# 其余：让现有 token 全部失效 / 下几次下载直接失败 / 人为延时以制造并发冲突 / 切换出现模式
curl -s -X POST localhost:18080/_fake/control \
  -d '{"expire_tokens": true, "fail_next": ["300-015"], "delay_seconds": 1.0, "emit_mode": "on_enter"}'

curl -s localhost:18080/_fake/state
```

## 覆盖的边界情况（NOTES.md 草稿第二节）

| # | 情况 | 怎么造出来 |
| --- | --- | --- |
| 1 | 通话进行中，尚无 -1 腿 | 「此刻」落在通话中途 |
| 2 | 时序倒置 | 注入 `inversion` |
| 3 | 回看窗口内重复取到 | 相邻窗口重叠；同一通呼叫在任何窗口取到的内容都一致 |
| 4 | 超过回看长度的长通话 | 约 5% 的通话长 16–45 分钟 |
| 5 | WAITBEGIN 为空 | 注入 `null_waitbegin` |
| 6 | CALLTYPE 不在值表内 | 注入 `unknown_calltype` |
| 7 | 同一 CALLID 内 CALLIDNUM 重复 | 注入 `dup_callidnum` |
| 8 | 腿恰在窗口边界上 | 部分呼叫恰在整分开始；窗口按 [起, 止) 半开区间 |
| 9 | 空结果 | 窗口在「此刻」之后，只返回表头 |

## 自测

```bash
python3 test/fake_icp/test_fake_icp.py -v
```

18 项，验的是假接口自己守住了约束、也真能造出上面的边界情况。这些测试做过反向验证：
把假接口的窗口上限、并发拒绝、乱序、半开区间、-1 腿判定逐一改坏，对应的测试都会失败。
