# infra —— 开发环境的构建与重建

这台机器的**唯一权威定义**。手敲的命令不算数——凡是让环境发生变化的操作，
都要落进 `playbooks/` 里的某个剧本，否则未来在离网环境重建不出来。

## 为什么这么严

生产环境无互联网出向（NW-03）。开发环境今天从外网拉的每一个包、每一个镜像，
将来都要从离线介质导入内网镜像源。**没有记录，到时候不知道要导入什么。**

因此两条纪律：

1. **凡引入外部依赖，当场在 `artifacts/MANIFEST.md` 记一行。** 不是事后补——
   事后补一定漏，而漏掉的恰恰是当时觉得「这个很常见不用记」的那些。
2. **凡改变机器状态，写进剧本。** 临时 `apt install` 一个包来排查问题，
   排查完要么写进剧本，要么卸掉。

## 目标机器

| 项 | 值 |
| --- | --- |
| 用途 | 团队共用的集成开发环境 |
| OS | Ubuntu Server 24.04 LTS (minimal) |
| 规格 | 16 vCPU · 64 GB · 800 GB SSD |
| 时区 | Asia/Riyadh（与生产一致，日切口径依赖它） |
| 语言环境 | en_US.UTF-8（系统英文，阿语只在数据与界面层） |

## 重建流程

```bash
# 1. 按 runbook/01-install-os.md 装系统（LVM 分卷）
# 2. 从任一台能 ssh 到目标机的机器上：
cd infra
ansible-playbook -i inventory/dev.yml playbooks/site.yml
# 3. 验证
ansible-playbook -i inventory/dev.yml playbooks/99-verify.yml
```

剧本必须**可重复执行**（幂等）。跑第二遍不应该报错，也不应该改变任何东西。
这是能否在离网环境可靠重建的前提——离网重建时没有人能临场调试。

## 目录

| 路径 | 内容 |
| --- | --- |
| `inventory/` | 主机与变量。**OS 与组件版本号写在这里，不写在剧本里** |
| `playbooks/` | 按阶段编号的剧本，`site.yml` 串起全部 |
| `artifacts/MANIFEST.md` | 外部物料清单。离网重建的物料依据 |
| `runbook/` | 装机步骤与排障手册。边搭边写，不要等搭完 |
| `files/` | 配置模板与静态文件 |

## 版本写在 inventory，不写在剧本里

八年合同期内必然要跨一次 OS 大版本和一次 PostgreSQL 大版本
（24.04 标准支持到 2029-04；PG 16 EOL 2028-11）。跨版本这件事无法避免，
能做的是让它变廉价——**版本是变量,剧本是逻辑**。写死版本号的剧本，
跨版本时要逐行改；版本参数化的剧本，改的是 inventory 里的几行。
