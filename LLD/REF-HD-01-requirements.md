# 需求规格说明书（HD-01）

> 每条需求的「验收标准」是判断实现是否完成的唯一依据。写不出可执行用例的验收标准，是需求本身的缺陷（见 LD-10 第 1 章）。

## REQ-DB-01  (L2 存储层)

- **需求**：单一高可用关系型数据库 以一个 PostgreSQL 集群实例承载全部 OSS911 相关数据，内部以七个 schema 逻辑分层。不引入第二种数据库产品或第二套分析引擎。
- **RFP 条款**：1.6.2.2 · 1.6.2.3
- **验收标准**：生产环境仅一个数据库集群实例；schema 清单与 HLD 5.1 一致；无其它数据库产品部署。
- **优先级**：必须

## REQ-DB-02  (L3 加工层 · L4 语义服务)

- **需求**：live 与 historical 数据的定义与实现 live 数据为当日数据，historical 数据为当日之前的数据。以日切与封账机制实现该区分，并在查询响应中标明封账状态。
- **RFP 条款**：1.6.2.4 · 1.6.2.4.1 · 1.6.2.4.2
- **验收标准**：当日数据标记为未封账；次日封账后标记为已封账并带版本号；同一报表在封账后重复运行结果一致。
- **优先级**：必须

## REQ-DB-03  (L2 · L6 监控)

- **需求**：容量与扩展规划 按业务规模基线提供容量规划，含分区策略、增长门限与扩容路径。
- **RFP 条款**：1.6.2.5 · 1.6.2.6 · 1.6.7.1
- **验收标准**：提交容量与性能分析文档；分区策略与保留期在库中实现；监控中存在容量水位告警门限。
- **优先级**：必须

## REQ-DB-04  (L4 记录检索服务)

- **需求**：跨库统一检索条件集 全部本方数据库以及经接口取得的遗留系统数据，可按统一的、可配置的检索条件集检索并即时调取记录。实现组件见 REQ-QRY-08。
- **RFP 条款**：1.6.2.7
- **验收标准**：统一检索条件集覆盖 core 层全部事实域，且对迁入的归档数据同样生效；操作员可按条件即时调出记录。
- **优先级**：必须

## REQ-DB-05  (项目管理 · L1)

- **需求**：数据源范围冻结 RFP 1.6.2.3 含"MOI 在设计阶段指定的任何其它关系型数据库"的开口表述。需在设计阶段形成书面冻结清单，此后新增数据源按变更处理。
- **RFP 条款**：1.6.2.3
- **验收标准**：存在经双方签署的数据源冻结清单；接入契约注册表条目与该清单一致。
- **优先级**：必须

## REQ-DB-06  (交付物 · L2)

- **需求**：交付非加密完整库副本与字典模型 向 MOI 交付关系型数据库格式的完整库副本（非加密），并附字段、表、视图、过滤器与报表的定义与说明、数据字典与数据模型，全部以 Microsoft Office 格式提供。
- **RFP 条款**：1.6.2.32
- **验收标准**：库副本可在标准 PostgreSQL 环境导入；字典与模型文档为 Word / Excel 格式且与实际库结构一致；随每次版本发布更新。
- **优先级**：必须

## REQ-ING-01  (L1 接入层)

- **需求**：可配置接入框架 接入以契约注册表驱动：水位线、幂等键、软删除、迟到窗口、调度、期望、契约版本均为配置项。新增数据源不需要编写新的调度代码。
- **RFP 条款**：1.6.2.1 · 1.6.2.3
- **验收标准**：新增一个数据源仅需一段契约与一个 staging 模型；批量作业由注册表生成；注册表在 Git 中版本化。
- **优先级**：必须

## REQ-ING-02  (L1 · L3)

- **需求**：DS CAD 展示库增量接入 以只读账号读取展示库基表，按水位线增量拉取，原样落 raw；语义映射在本方 staging 层完成。
- **RFP 条款**：1.6.2.1 · 1.6.2.3
- **验收标准**：增量拉取无漏数（以回看窗口与幂等键验证）；raw 层保留原始载荷；映射登记表与验证样例齐备。
- **优先级**：必须

## REQ-ING-03  (L1 · L3)

- **需求**：话务与录音数据接入 接入话务平台的呼叫明细、坐席状态与录音元数据。RFP 要求经本方提供的 ESB 集成，现场沟通为 ICP 仅提供 REST 接口，两者的关系需确认（见假设登记册 AS-05）。
- **RFP 条款**：2.6.1.26 · 2.6.2.15.9 · 2.6.2.19.3
- **验收标准**：呼叫明细与坐席状态可支撑 1.6.2.20.1 至 1.6.2.20.5 的全部指标；录音元数据可关联到警情与通话。
- **优先级**：必须

## REQ-ING-04  (L1 · L3 · L5)

- **需求**：客户反馈接入 将客户反馈纳入 BI，作为 OSS911 绩效度量的组成部分。反馈的采集渠道与数据形态待确认。
- **RFP 条款**：1.6.2.17
- **验收标准**：反馈数据进入 core 层并可按时间、辖区、单位与警情类型分析；至少一个仪表板与一张报表包含反馈指标。
- **优先级**：必须

## REQ-ING-05  (L1)

- **需求**：外部 Kafka 消费能力 不自建 Kafka 代理，但具备消费能力。主题命名、消息格式、幂等键与位点语义先行定义，上线时不启用。
- **RFP 条款**：—
- **验收标准**：存在契约定义与一个可运行的消费端联调用例。
- **优先级**：预留

## REQ-ING-06  (L1)

- **需求**：结构漂移检测 每次拉取前抓取源库结构快照并与上次比对，结构变化时隔离该批并告警。
- **RFP 条款**：2.7.7.9
- **验收标准**：人为改动测试源库结构后，系统隔离该批数据并产生告警，不将未知变更带入下游。
- **优先级**：必须

## REQ-ING-07  (L3 · M-03)

- **需求**：值剖析与待澄清队列 对代码与枚举字段持续剖析取值分布，未映射取值不得静默归入"其他"，按影响面排序进入待澄清队列。
- **RFP 条款**：2.7.9.2
- **验收标准**：M-03 界面可见待澄清清单并可排序；未映射取值日占比超阈值时告警。
- **优先级**：必须

## REQ-ING-08  (L1 · L3)

- **需求**：多版本 schema 归一化 支持历史数据集在时间轴上存在多个 schema 版本，具备摄取、映射与归一化能力。需向 MOI 索取 Hexagon 的历史升级记录。
- **RFP 条款**：2.7.7.9
- **验收标准**：对至少两个不同 schema 版本的历史数据集完成归一化并通过对账。
- **优先级**：必须

## REQ-MIG-01  (L1 归档迁移工具)

- **需求**：历史数据迁移 将麦加 911 中心既有历史数据迁入本方中央库。旧系统完成对账后下线。
- **RFP 条款**：2.7.7.1 · 1.6.2.1
- **验收标准**：迁移完成报告；源端与目标端记录数与关键字段一致。
- **优先级**：必须

## REQ-MIG-02  (L1 · L3 数据质量)

- **需求**：记录级全量对账 迁移后进行完整的数据对账与校验，达到记录级，不得仅依赖统计抽样。
- **RFP 条款**：2.7.7.10
- **验收标准**：对账覆盖 100% 记录；差异为零，或每一条差异有书面原因与处置结论。
- **优先级**：必须

## REQ-MIG-03  (L3 · L4)

- **需求**：历史与新数据统一查询 授权用户可无缝查询历史与新数据，无需人工干预；无论数据为历史或当期，报表口径一致。
- **RFP 条款**：2.7.7.13
- **验收标准**：同一张报表跨迁移时点的时间范围可一次查出；口径说明中无历史/当期分支。
- **优先级**：必须

## REQ-MIG-04  (项目管理)

- **需求**：迁移责任边界 历史数据迁入"本方中央库"与迁入"DS 新 CAD 业务库"是两件事，责任边界须书面划清。
- **RFP 条款**：2.7.7.1
- **验收标准**：存在经确认的边界说明：本方负责迁入中央库；CAD 业务库的历史装载由 DS 负责。
- **优先级**：必须

## REQ-MOD-01  (L2)

- **需求**：七层 schema 结构 raw / staging / core / mart / ai / meta / audit，职责与可重建性按 HLD 5.1。
- **RFP 条款**：1.6.2.2
- **验收标准**：库中存在且仅存在这七个业务 schema；raw 层记录带 run_id、contract_version 与源水位。
- **优先级**：必须

## REQ-MOD-02  (L3)

- **需求**：core 为唯一事实来源 mart 与 ai 均自 core 构建，任何一方不得自行从 raw 另起加工链。
- **RFP 条款**：1.6.2.2 · 1.6.2.19
- **验收标准**：血缘图显示 mart 与 ai 的全部上游均为 core；代码评审规则禁止 mart / ai 直接引用 raw。
- **优先级**：必须

## REQ-MOD-03  (L3 · L2)

- **需求**：缓变维 Type 2 坐席、班组、单位、辖区、警情分类等维度按"当时"记录，维度表存生效与失效时间。
- **RFP 条款**：2.7.7.13
- **验收标准**：构造维度变更后重跑历史报表，数值不变。
- **优先级**：必须

## REQ-MOD-04  (L3)

- **需求**：通话与警情的关联 利用两侧统一的通话标识建立呼叫与警情的关联，支撑从振铃到出警的全过程指标。关联基数（一警情多通话、无通话标识的警情）须以真实数据验证。
- **RFP 条款**：1.6.2.20 · 1.6.2.16.4
- **验收标准**：全过程时长指标可计算并通过样例核对；关联率与未关联原因有统计。
- **优先级**：必须

## REQ-MOD-05  (L2 · L3)

- **需求**：站点维度与全局唯一主键 全部事实表带 dim_site；主键在全局范围内唯一，不依赖单站自增序列。
- **RFP 条款**：1.6.2.33
- **验收标准**：事实表 DDL 含 dim_site；主键生成策略文档化并通过跨站合并模拟测试。
- **优先级**：必须

## REQ-MOD-06  (L2)

- **需求**：分区与保留 按天分区。在线保留按 RFP 2.7.10.4.1 为一年（热层），一年以上的全部历史在线保留于 core 并走历史查询路径（温层），备份按离线五年与扩展离线八年执行（冷层）；raw 层按合同期保留，audit 按合规要求保留。详见 REQ-BAK-04。原「业务数据在线保留八年」为对 2.7.10.4 的口径误读，已更正。
- **RFP 条款**：1.6.2.5 · 1.6.2.6
- **验收标准**：分区自动创建与归档；三层保留策略在库与备份中分别实现且可核查。
- **优先级**：必须

## REQ-MOD-07  (L2 · L4 AI 数据服务)

- **需求**：AI 数据层 实体级宽表、特征表、媒体索引与导出快照，供未来 AI 使用。本方不交付 AI 模型。

## REQ-MOD-08  (交付物)

- **需求**：数据字典与模型文档 数据字典与数据模型随版本维护，与库结构保持一致，作为交付物提交。
- **RFP 条款**：1.6.2.32
- **验收标准**：字典与模型由库结构自动生成并人工补充业务含义；每次发布同步更新。
- **优先级**：必须

## REQ-QRY-01  (L4 · L5)

- **需求**：授权用户的常规与临时查询 授权用户可查询并生成报表，既支持常规（预置）也支持临时（ad-hoc）。RFP 所要求的 smart and AI-powered 能力由联合体内 AI 包实现，本方提供语义目录与结构化查询接口（REQ-API-05）供其调用；对外为整体承诺，本方与 AI 包的划界不写入投标文件。
- **RFP 条款**：1.6.2.8 · 1.6.2.10
- **验收标准**：预置查询与临时查询均可执行；结果可导出；AI 包可经语义目录接口完成一次自然语言取数联调。
- **优先级**：必须

## REQ-QRY-05  (L4 · L5 · L6 审计)

- **需求**：受控 SQL 查询能力 RFP 要求可使用通用 SQL 生成简短报表。提供受控的 SQL 查询能力：仅限授权角色、只读、仅在分析副本执行、强制超时与结果集上限、全程审计。此项是对"不允许绕过语义层"的例外，需以权限与审计约束。
- **RFP 条款**：1.6.2.15
- **验收标准**：授权用户可执行只读 SQL；非授权角色不可见该功能；所有 SQL 执行记录进入 audit；存在超时与行数上限。
- **优先级**：必须

## REQ-QRY-08  (L4 记录检索服务)

- **需求**：记录检索服务 与聚合查询 API 并列的记录级检索能力。检索条件为可配置的有限集合，每条对应索引；时间范围必填且有最大跨度上限；结果集有硬上限，超限要求收窄条件；一律走分析副本，配额独立；归档迁移数据纳入同一检索面；移动端受众一律拒绝。返回字段按角色的可见性矩阵裁剪。

- **优先级**：必须

- **需求**：许可的集中安装、激活与管理 提供集中安装、激活与管理全部软件许可的方案。开源组件无激活概念，需以组件与版本清单管理替代，并在方案中说明。
- **RFP 条款**：2.7.3.6
- **验收标准**：存在集中的组件与版本清单管理能力；说明已提交并获认可。
- **优先级**：必须

## REQ-LIC-08  (L6 · 交付流程)

- **需求**：合同期内保持更新与补丁 在合同期内负责将交付的软件与方案保持在最新稳定版本，含更新、升级与补丁。须与无外网环境（REQ-SEC-06）及 COTS 五年不 EOL 的要求（REQ-LIC-02）协调一致。
- **RFP 条款**：2.7.3.7
- **验收标准**：存在版本基线与补丁流程；每次补丁经测试环境验证后进入生产；版本变更记录可核查。
- **优先级**：必须

## REQ-MOD-09  (L1 · L3)

- **需求**：资源数据经 CAD 取得 与 MOI 指定来源的资源数据（经 ESB 自国家数据中心取得的人员与车辆信息、经外部接口取得的报警人位置等）由 CAD 在业务处理中获取并落库，本方从 DS 展示库一并取得，不直连外部系统，不新增数据源。CAD 对这些信息的落库形态须逐项确认。
- **RFP 条款**：1.6.3.1
- **验收标准**：资源类数据可从展示库取得并落库；来源与落库形态清单经确认；资源可用率与位置类指标的可行性有书面结论。
- **优先级**：必须

## REQ-MOD-10  (L6 · M-10)

- **需求**：库的管理与维护操作 授权用户可对集成的关系型数据库执行创建、更新、删除等全部管理与维护操作。此项须与"服务层唯一出口"的约束协调：管理操作经管理界面进行，并受角色、审计与变更流程约束，不等同于开放直连数据库。
- **RFP 条款**：1.6.3.4
- **验收标准**：管理操作可在 M-01 至 M-11 中完成；全部操作留痕；无需绕过服务层直连库。
- **优先级**：必须
